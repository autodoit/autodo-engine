# 用户手册

autodo-engine 提供运行时初始化、图注册、任务推进、审计查询与事务直调能力。

支持两种模式：

- 独立模式：仅安装 autodo-engine，使用引擎内置事务与内置工具。
- 增强模式：同时安装 autodo-kit，自动扩展官方事务与工具。

## 当前与任务管理系统升级相关的使用边界

如果当前关心的是“AOE 是否已经升级为正式任务管理系统”，应按下面口径理解。

已经可用：

1. AOE 已能作为固定主链运行时，负责任务创建、单步推进、持续推进、暂停、恢复、阻断审计与事务直调。
2. AOE 当前已经具备 `ready`、`running`、`suspended`、`blocked`、`completed`、`failed`、`cancelled` 这套任务状态机，并支持 `split`、`human_gate` 等动作语义。
3. AOE 已支持正式的 `事务请求` 对象，可以创建、查询和回写请求状态。
4. AOE 已支持正式的 `决策部门` 对象，默认包含人类成员与阿里百炼 LLM 成员。
5. 若同时安装 autodo-kit，AOE 可以通过事务注册系统直接调用官方 affair。

当前还不能直接指望它做的事：

1. AOE 主循环目前不会自动把 `事务请求` 纳入统一候选调度。
2. 默认决策部门当前首先承担治理配置与审计底座角色，尚未自动发起真实的人类审批或阿里百炼模型调用。
3. “属性向量调度、双维任务网络横向依赖物理化、统一事务请求排队与抢占”仍属于后续设计目标。

因此当前推荐口径是：

1. 要跑固定主链，用 AOE 的 task / graph 运行接口。
2. 要登记一个独立事务需求，用 AOE 的事务请求 API 或 CLI。
3. 要单独执行某个官方事务，用 `run_affair(...)`。
4. 如果当前节点是 A055，并且你明确选择了 `A055.mode.*.minimal.json` 这四个直跑配置之一，那么应直接走 AOK official affair，不要再先交给 AOE 包装成单节点主链。
5. 解析结果巡检优先看 `文献主表.解析状态` 或中文总视图里的 `解析状态`；`当前解析状态` 仍只表示当前 parse asset 的低层状态。
6. 不要把 AOE 当前版本理解成“已经完成事务请求统一调度与自动 LLM 决策的最终系统”。

## AOE 主链资产位置

AOE 固定主链的 workflow 资产与 runtime 留痕已统一放在：

`${HOME}/ProjectsFile/autodo-engine/workflows/workflow_20260417_aoe_mainflow_v1/`

其中：

- 静态图源文件：`academic-research-mainflow-v1.aof.md`
- 可执行图文件：`academic-research-mainflow-latest.json`
- 运行时留痕目录：`runtime/aok-mainflow-v1/`

## 1. 安装

```powershell
uv pip install -e .
```

可选安装增强包：

```powershell
uv pip install -e ../autodo-kit
```

## 2. 初始化运行时

```powershell
python -m autodoengine.main init-runtime --base-dir ./.tmp/runtime_v4
```

## 3. 注册流程图并创建任务

```powershell
python -m autodoengine.main register-graph --graph-file workflows/workflow_20260308_all_affairs_demo/workflow.json
python -m autodoengine.main create-task --title "示例任务" --goal-text "验证运行链路" --current-node-uid node-start
```

## 4. 推进任务

```powershell
python -m autodoengine.main run-task-step --task-uid <task_uid> --graph-uid <graph_uid>
python -m autodoengine.main run-task --task-uid <task_uid> --graph-uid <graph_uid> --max-steps 50
```

## 5. 创建与查看事务请求

```powershell
python -m autodoengine.main create-task-request --request-type "事务执行" --target-affair-uid "图节点_start" --task-uid <task_uid> --source-object-type "节点" --source-object-uid "A010" --node-code "A010" --config-path "workspace/config/affairs_config/A010.json" --request-contract-json '{"entry_config":"workspace/config/affairs_config/A010.json"}' --payload-json '{"workspace_root":"."}'
python -m autodoengine.main show-task-request --request-uid <request_uid>
python -m autodoengine.main list-task-requests --task-uid <task_uid>
```

当项目本身采用“项目经理先解 `config.json`，再下发 `node_inputs` / `node_contracts`”的模式时，推荐把节点编码、配置路径和节点契约一并写入请求对象，便于后续调度与回放。

## 6. 查看决策部门与成员

```powershell
python -m autodoengine.main show-decision-departments
python -m autodoengine.main show-decision-department-members --department-uid dept-default
```

## 7. 查看审计与数据库路径

```powershell
python -m autodoengine.main show-task --task-uid <task_uid>
python -m autodoengine.main show-decisions --task-uid <task_uid>
python -m autodoengine.main show-runtime-events --task-uid <task_uid>
python -m autodoengine.main show-runtime-store-paths --base-dir ./.tmp/runtime_v4
python -m autodoengine.main show-affair-registry-paths --workspace-root .
```

## 8. 统一 capability 调用

列出 capability：

```powershell
python -m autodoengine.main list-capabilities
```

执行 capability：

```powershell
python -m autodoengine.main invoke-capability --capability-id affair_refresh --payload-json '{"workspace_root":"."}'
```

校验 capability manifest/schema：

```powershell
python -m autodoengine.main lint-capabilities
```

## 9. Python 方式调用 capability

```python
from pathlib import Path
from autodoengine import api

result = api.invoke_capability(
    "affair_show_paths",
    payload={"workspace_root": str(Path.cwd())},
    workspace_root=Path.cwd(),
)
print(result)
```

## 10. Python 方式调用事务请求与决策部门

```python
from autodoengine import api

request = api.create_task_request(
    request_type="事务执行",
    target_affair_uid="图节点_start",
    source_object_type="节点",
    source_object_uid="A010",
    node_code="A010",
    config_path="workspace/config/affairs_config/A010.json",
    request_contract={"entry_config": "workspace/config/affairs_config/A010.json"},
    payload={"workspace_root": "."},
)
print(request)

department = api.get_decision_department()
members = api.list_decision_department_members()
print(department)
print(members)
```

如果项目已经采用 `config.json + node_inputs + node_contracts` 的项目经理编排模式，可以直接用更高层的 builder：

```python
from autodoengine import api

request = api.create_task_request_from_project_node(
    project_config_path="workspace/config/config.json",
    node_code="A010",
    task_uid="task-demo",
)
print(request)
```

## 11. 直接调用事务

```python
from pathlib import Path
from autodoengine import api

api.run_affair(
    "图节点_start",
    config={"output_dir": "output/demo"},
    workspace_root=Path.cwd(),
)
```

复合事务示例：

```python
api.run_affair(
    "引擎能力巡检",
    config={"output_dir": "output/inspection"},
    workspace_root=Path.cwd(),
)
```

## 12. Runner 参数文件调用

```powershell
python scripts/invoke_capability.py path/to/params.json
```

说明：

- 事务解析、冲突检测、用户覆盖规则在本仓执行。
- 已安装 autodo-kit 时，官方事务源码与事务文档优先来自 autodo-kit。
- 未安装 autodo-kit 时，自动回退到 `autodoengine/affairs` 与 `autodoengine.tools`。
- capability 调用会自动产出审计文件到 `.autodoengine/tool_audits/`。
