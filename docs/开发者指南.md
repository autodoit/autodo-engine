# 开发者指南

autodo-engine 负责运行时框架本身。开发引擎功能时，应优先保持调度、协议、审计与事务注册的边界清晰。

当前约定：引擎仓内保留最小可运行事务与最小工具集，保障“仅安装 engine 可跑 demo”；业务扩展能力由 autodo-kit 提供。

## 1. 架构分层

- autodoengine/core：类型、枚举、错误
- autodoengine/flow_graph：图加载、模板、编译与运行期节点结构
- autodoengine/scheduling：单步主循环、候选动作、决策规则、路由守卫
- autodoengine/taskdb：任务、步骤、日志、决策、快照、审计视图
- autodoengine/utils：路径、配置、事务注册、表达式与运行辅助
- autodoengine/tools/atomic：原子工具能力实现
- autodoengine/tools/public：manifest、schema、协议、权限、审计、facade
- autodoengine/tools/adapters：CLI、Python、Agent、Runner 统一入口

## 2. 与 autodo-kit 的边界

1. 引擎仓内保留最小事务目录 `autodoengine/affairs`，用于独立运行与最小 demo。
2. 若已安装 autodo-kit，事务扫描优先使用 `autodokit/affairs`；未安装时回退到 `autodoengine/affairs`。
3. run_affair、build_registry 同时兼容 `autodokit.affairs.*` 与 `autodoengine.affairs.*` runner 模块路径。
4. list_tools/get_tool 优先桥接 `autodokit.tools`；未安装时回退到 `autodoengine.tools`。

## 2.1 当前任务管理系统能力口径

围绕“AOE 从固定主链 runner 升级为更强的任务管理系统”这条设计线，当前能力应按下面口径理解。

已完成：

1. `autodoengine.core.enums` 已定义正式任务状态：`ready`、`running`、`suspended`、`blocked`、`completed`、`failed`、`cancelled`，并提供中文持久化映射。
2. `autodoengine.taskdb.state_machine` 已实现合法状态迁移约束，能够明确区分恢复、阻断、完成、失败与取消。
3. `autodoengine.scheduling.task_loop` 已支持 `continue`、`retry`、`backtrack`、`suspend`、`split`、`human_gate`、`complete`、`fail`、`cancel` 等动作语义，并能输出决策与运行审计。
4. `autodoengine.taskdb` 已形成 SQLite 主链，包括任务主表、任务步骤、任务关系、决策记录、运行事件与任务快照。
5. `autodoengine.taskdb.request_store` 已把 `事务请求` 作为正式 SQLite 对象接入引擎 API/CLI，可进行创建、读取、列表与状态回写。
6. `事务请求` 当前已具备项目接洽桥接字段：`来源对象类型`、`来源对象UID`、`节点编码`、`配置路径`、`请求契约JSON`，用于承接项目经理已经解析好的节点上下文。
7. `autodoengine.api.create_task_request_from_project_node(...)` 已提供一个通用 builder，可直接从项目级 `config.json` 与 `node_code` 构造标准请求对象。
8. `autodoengine.taskdb.request_store` 已补齐请求协调字段：`调度状态`、`uid_执行者`、`资源指纹`、`幂等键`、`预期版本`、`快照令牌`、`租约过期时间`、`提交状态`。
9. `autodoengine.taskdb.request_store` 已新增 `资源租约` 与 `执行者心跳` 两张中文主契约表，支持领取、续租、释放、过期回收与心跳更新。
10. `autodoengine.api.run_task_request(...)` 已接入“领取租约 -> 执行 -> 待提交 -> 已提交 -> 完成/失败 -> 释放租约”执行链。
11. `autodoengine.api` 已新增 `list_schedulable_task_requests(...)`、`acquire_task_request_lease(...)`、`renew_task_request_lease(...)`、`release_task_request_lease(...)`、`upsert_task_request_executor_heartbeat(...)`。
12. `autodoengine.taskdb.department_store` 已把 `决策部门`、`决策成员` 作为正式 SQLite 对象接入引擎 API/CLI，并自动确保默认“人类 + 阿里百炼 LLM”治理配置存在。
13. `get_task_full_chain_view(...)`、`get_decision_department_view(...)`、`get_blocked_governance_view(...)` 已提供任务链、决策部门与阻断治理视角。
14. 旧的 CSV/schema/integrity 简单骨架已迁移到 `autodoengine/backup/taskdb_legacy/`，不再与主 `taskdb/` 路径混放。

当前仍未完成：

1. `run_task_until_wait(...)` 与主循环仍以任务节点推进为主，尚未把事务请求队列并入统一候选排序。
2. 决策部门当前首先承担治理配置与审计底座角色，调度器尚未在每一轮请求调度中自动外发人类/LLM 执行链。
3. 横向前后依赖关系仍主要通过任务步骤与事务请求组合表达，尚未单独物理化为完整依赖网络。

开发口径要求：

1. 可以把当前系统描述为“具备正式事务请求对象与决策部门对象的任务管理系统基础版”。
2. 可以把当前系统描述为“已具备请求租约与执行者心跳协调能力的任务管理系统增强版”。
3. 不应把当前系统描述为“已经完成任务主循环与事务请求队列的统一全局调度”。
4. 后续调度增强应优先在主循环候选层完成，而不是绕回到零散的业务事务内部实现。

## 3. 包与入口

- Python 包名为 autodoengine
- CLI 入口为 autodoengine.main
- 对外 API 入口为 autodoengine.api

## 5. 多入口约束

1. CLI、Python、Agent、Runner 不直接承载业务逻辑，只调用 `public.facade.invoke_capability`。
2. capability 输入/输出必须在 manifest/schema 中声明。
3. capability 调用默认写入审计记录到 `.autodoengine/tool_audits/`。
4. 新增 capability 时，必须同步补齐 schema、lint 回归和文档。

## 6. 开发约束

1. 新增路径字段时，先接入 utils/path_tools 的统一绝对路径预处理。
2. 不在调度层硬编码事务仓目录，统一通过事务注册系统发现。
3. docs 中涉及 CLI、包名、模块路径时必须使用 autodoengine 口径。
4. 新 capability 优先落在 `atomic/*`，根 `tools/` 不再新增平铺业务文件。
5. 运行时数据库的物理主契约应保持中文；只有专有英文缩写、`uid_` 标识和必要技术键保留英文。
6. 若需要保留历史任务系统骨架，应迁入 `backup/`，不要继续堆放在主 `taskdb/` 目录干扰当前实现。
