# AOE任务数据库协调调度开发与改造方案

## 一、目标与范围

本方案用于把 AOE 任务数据库从“请求登记能力”升级为“可协调多 agent 并发执行”的轻量调度系统。

目标：

1. 在不引入复杂分布式组件的前提下，完成 SQLite 场景的并发协调闭环。
2. 保持表结构简洁，以表承载状态，以视图承载阅读聚合。
3. 统一中文命名口径，除 `uid_` 前缀外不新增英文业务字段名。

范围：

1. `autodoengine/taskdb/request_store.py`
2. `autodoengine/api.py`
3. `autodoengine/taskdb/__init__.py`
4. `autodoengine/__init__.py`
5. `tests/test_taskdb_request_department_store.py`
6. `docs/API手册.md`
7. `docs/开发者指南.md`

## 二、现状问题

1. 事务请求表已存在，但缺少租约、执行者、提交阶段等协调字段。
2. 缺少资源租约表，无法稳定约束同一请求的并发领取。
3. 缺少执行者心跳表，无法识别执行者存活与接管时机。
4. `run_task_request` 执行链缺少“领取租约-执行-提交-释放租约”标准流程。

## 三、改造原则

1. 先补数据结构，再补 API，再补流程。
2. 每一步都保证可回滚、可测试。
3. 保持最小破坏，优先增量扩展现有接口。
4. 不引入跨进程消息中间件，先以 SQLite 表实现协调。

## 四、实施步骤

### 步骤1：扩展事务请求主表

1. 增加调度与协调字段：调度状态、`uid_执行者`、资源指纹、幂等键、预期版本、快照令牌、租约过期时间、提交状态。
2. 增加必要索引：请求状态与优先得分索引、执行者索引。

产出：

1. 请求可表达完整生命周期。

### 步骤2：新增资源租约表与执行者心跳表

1. 新增资源租约表，支持领取、续租、释放、过期回收。
2. 新增执行者心跳表，支持活跃状态与当前请求记录。

产出：

1. 并发领取冲突可控。
2. 过期接管有数据依据。

### 步骤3：实现 request_store 协调接口

1. 查询可调度请求。
2. 领取请求租约。
3. 续租与释放。
4. 更新执行者心跳。
5. 推进请求为待提交、已提交、已完成等阶段。

产出：

1. 存储层具备最小可用调度能力。

### 步骤4：接入 API 与执行流程

1. 在 `api.py` 暴露协调接口。
2. 改造 `run_task_request`：
   - 先领取租约
   - 再推进执行
   - 再推进提交
   - 最后释放租约
3. 保持既有调用方式可用。

产出：

1. AOE 主执行路径完成协调闭环。

### 步骤5：测试与文档同步

1. 增加租约并发测试、过期接管测试、状态推进测试。
2. 更新 API 手册与开发者指南。
3. 回归现有请求/部门相关测试。

产出：

1. 功能可验证。
2. 文档与实现一致。

## 五、验收清单

1. 同一请求不能被两个执行者同时领取。
2. 租约过期后可被其他执行者领取。
3. `run_task_request` 在成功与失败路径都能正确释放租约。
4. 请求状态链路包含待调度、已租约、执行中、待提交、已提交、已完成。
5. 数据库对象命名符合中文主契约与 `uid_` 例外规则。

## 六、风险与控制

1. 风险：旧请求数据不含新字段。
   - 控制：通过 `_ensure_column` 自动补齐字段并设置默认值。
2. 风险：历史调用方依赖旧状态集合。
   - 控制：保留原状态值并做向后兼容映射。
3. 风险：执行中进程异常退出导致租约悬挂。
   - 控制：过期扫描与接管机制。

## 七、完成定义

以下条件全部满足视为完成：

1. 数据结构与接口改造完成并通过测试。
2. 关键请求调度链路通过自动化验证。
3. 文档已同步且可独立指导后续扩展。
